# Polityka bezpieczeństwa

## Wspierane wersje

Poprawki bezpieczeństwa są przygotowywane dla najnowszego opublikowanego
wydania. Starsze wersje należy najpierw zaktualizować.

## Zgłaszanie podatności

Nie publikuj informacji o podatności ani działającego exploita w zwykłym issue.
Użyj prywatnego zgłoszenia bezpieczeństwa GitHub (zakładka **Security**,
**Report a vulnerability**). Jeżeli prywatne zgłoszenia nie są jeszcze włączone,
zgłoś wyłącznie potrzebę prywatnego kontaktu bez ujawniania szczegółów luki.

W zgłoszeniu podaj:

- wersję BlackHost CLI i system operacyjny;
- komponent oraz warunki odtworzenia problemu;
- możliwy wpływ;
- bezpieczny, minimalny przykład odtworzenia.

Przed dołączeniem logów usuń hasła, tokeny, domeny klientów, publiczne adresy IP
i inne dane umożliwiające identyfikację infrastruktury.
